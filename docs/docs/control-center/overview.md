The landing page. It does not need the server to be running - it is the page you use when it is not.

## Environment readiness

Seven checks, each with a state and the path it resolved. Anything not ready gets an Install button next to it, and **Install missing** runs .NET, mitmproxy and the certificate in sequence. **Re-check** runs the checks again.

| Row | Ready means | Notes |
| --- | --- | --- |
| .NET SDK | `dotnet --version` answered | installed from the official installer |
| Server build | an executable was found | warns when the build is older than the source, or when the recorded release version does not match the build |
| Game database | `shittim.sqlite3` exists | warns rather than fails when it does not; it is created on the first run |
| mitmproxy | `mitmweb --version` answered | the detail says which `mitmweb` it found |
| CA certificate | the root certificate is trusted | generated by running mitmproxy once |
| Gateway keys | `GatewayPrivateKey.pem` is next to the exe, or in `Shittim-Server/config` waiting to be copied on build | without it the login handshake cannot be decrypted |
| Redirect script | `redirect_server.py` exists | |

## Offline mode

**Start offline** brings the server and the proxy up with their offline switches on and rewrites the hosts file so every hostname the client contacts resolves to loopback. Nothing the game asks for then needs a name server or a route out.

The line under the buttons says how many hostnames are currently redirected. Stopping the server restores the file; **Restore hosts file** does it by hand if that did not happen.

Steam still has to be running, offline or not.

This is currently extremely buggy, it may work, but it also may not.

## Shortcuts

Four buttons that open the server folder, the proxy scripts folder, `Config.json` and the database in Explorer.

## Diagnostics

**Export logs** bundles the server log and a diagnostic snapshot into a zip and reveals it in Explorer. That zip is what to attach to a bug report.
